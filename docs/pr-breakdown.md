# Объём и приёмка плановых PR

Это backlog реализации, а не отчёт о выполненном коде. Порядок и проверки H1/H2 — в [плане](plan.md); исходные требования — в [ТЗ](spec.md). Каталоги и команды ниже обозначают будущую структуру приложения.

## PR-01 — Основа приложения и конфигурация

**Зависимости:** нет. **Ветка:** `feat/bootstrap-config`.

**Изменения:** пакет `src/call_secretary`, Python 3.12, описание и фиксация зависимостей, CLI `check-config`/`status`, журналы без содержимого разговоров, CI для форматирования, статической проверки и содержательных тестов. Раздельные режимы `simulation` и `live`; проверка схемы настроек и семейных профилей. Секреты и реальный `family.yaml` остаются вне Git.

**Готово, когда:** новый checkout устанавливается по инструкции; `check-config` принимает синтетический пример и объясняет неверные настройки. Simulation работает без сети и ключей; live не стартует с пустой конфигурацией. CI воспроизводимо проходит без секретов, аудиозаписей и личных данных.

## PR-02 — Диагностика модема и стенд H1/H2

**Зависимости:** PR-01. **Ветка:** `feat/modem-preflight`.

**Изменения:** CLI поиска выделенного устройства по стабильному идентификатору, инвентаризация интерфейсов/владельца портов, модели, прошивки и регистрации; ограниченные по времени AT-запросы. По умолчанию только диагностика. Отдельный стенд для пробного ответа/отбоя и тестового звука в обе стороны без записи разговора. Протокол H1/H2 с фактическим результатом либо «не проверено». Инструменты не отключают ModemManager глобально и не сбрасывают соседние USB-устройства.

**Готово, когда:** симуляция устройств покрывает отсутствие модема, занятый порт, переподключение и похожие интерфейсы; неоднозначный выбор завершается ошибкой. Инструментальный PR можно смерджить без оборудования. H1/H2 отмечаются пройденными только после реального испытания; номера и сырые приватные ответы не публикуются.

## PR-03 — Постоянное состояние и история

**Зависимости:** PR-01. **Ветка:** `feat/persistent-state`.

**Изменения:** модуль `storage/`, SQLite со схемой и миграциями: звонки, текстовые реплики, профиль/источник маршрута, задачи резюме, очередь Telegram, расходы и резервы. Транзакции и восстановление незавершённой обработки; ID звонка создаётся до внешних действий. Текст не имеет автоматического срока удаления.

**Готово, когда:** рестарт сохраняет звонок, назначение и задачи; сбой посреди транзакции не оставляет частичный результат. Проверены миграция с данными, повторное открытие БД и сохранение старого текста. Недоступное хранилище не вызывает скрытого перехода к состоянию только в памяти. Схема не содержит аудио и сырых событий с аудиопакетами.

## PR-04 — Семейные профили и маршрутизация

**Зависимости:** PR-01, PR-03. **Ветка:** `feat/family-routing`.

**Изменения:** модуль `routing/`, три профиля с приветствиями, вариантами имён, правилами, языком отчёта и Telegram-назначением. Раздельные `caller_number`, `original_called_number`, `ingress_id`; автоматический выбор только по проверенному правилу. Общая линия без адресата переходит к уточнению. Номера и привязки чатов находятся в закрытой конфигурации.

**Готово, когда:** одинаковый звонящий независимо попадает в три профиля; скрытый caller ID не меняет адресата; непроверенные метаданные не включают автоматическую маршрутизацию. Неизвестное имя и совпадающие варианты требуют уточнения. До выбора профиля звучит общее приветствие; источник выбора сохраняется вместе со звонком.

## PR-05 — Бюджет и независимые ограничения разговора

**Зависимости:** PR-03. **Ветка:** `feat/usage-budget-guards`.

**Изменения:** модуль `budget/`, общий лимит €50 на календарный месяц Europe/Rome, постоянный учёт расходов и атомарные резервы. До голосового сеанса резервируется консервативная стоимость предельного разговора и последующего резюме по проверенным тарифам/курсу; затем учитывается доступное фактическое usage. Неопределённый расход после сбоя не становится автоматически нулевым. Монотонный таймер 600 секунд с закрывающей репликой до жёсткого отбоя. Служебная фраза для работы без API создаётся отдельно из текста и не является записью звонка.

**Готово, когда:** управляемые часы/тарифы покрывают последний доступный резерв, конкурирующие резервы, рестарт, смену месяца, разговор через границу месяца и неизвестную цену. При недостатке бюджета платный запрос не отправляется; зависание модели не отменяет предел времени. Неизвестные расходы сохраняются для сверки. Документация различает оценку приложения и окончательный биллинг провайдера.

## PR-06 — Голосовой API и прототип на компьютере

**Зависимости:** PR-04, PR-05. **Ветка:** `feat/realtime-voice-prototype`.

**Изменения:** адаптер realtime API, конфигурируемые модель/голос, микрофон и динамик стенда; аудио проходит через ограниченные буферы памяти. Итальянское приветствие и переход на язык звонящего; текстовые события, usage, перебивание и отмена воспроизведения. До реализации проверяются актуальные официальные API-документы, тарифы, форматы и условия выбранного голосового сервиса; версия протокола не выбирается по памяти.

**Готово, когда:** поддельный транспорт покрывает обрыв, неверный ключ, ограничение API, отмену и поздние аудиособытия; память не растёт с длительностью разговора. В живом прослушивании проверены IT/RU/EN, голос и перебивание; измерены задержка/стоимость без записи аудио. Платный сеанс открывается после резервирования. Для живой приёмки нужны API и микрофон, модем не нужен.

## PR-07 — Управление разговором и выбор адресата голосом

**Зависимости:** PR-04, PR-05, PR-06. **Ветка:** `feat/call-controller`.

**Изменения:** `calls/`: состояния входящего вызова, уточнения адресата, диалога, завершения и ошибки; поддельный телефонный адаптер. Модель предлагает только разрешённый профиль, окончательный переход выполняет код. Ограничение попыток выбора и ожидания ответа; при неуспехе звонок остаётся нераспределённым. Выбор подключает инструкции профиля; перебивание очищает устаревшее воспроизведение. Отбой, тишина, лимит и ошибка API завершают звонок согласованно.

**Готово, когда:** воспроизводимы три адресата, смена языка, неоднозначное имя, молчание и отбой на каждой стадии. Повторный отбой/поздние события не запускают второй разговор или вторую задачу обработки. Чужие инструкции не применяются до выбора профиля; слова звонящего не задают произвольный Telegram chat ID. Доступна голосовая демонстрация без модема.

## PR-08 — Резюме и очередь обработки после звонка

**Зависимости:** PR-03, PR-05, PR-07. **Ветка:** `feat/call-summaries`.

**Изменения:** `summaries/`: финализация текста и структурированное резюме — имя/организация, доступный caller ID, цель, срочность, обратный контакт, следующий шаг, язык и неизвестные сведения. Русский по умолчанию, настройка по профилю. Задача переживает рестарт; готовое резюме и доставка сохраняются транзакционно. Нераспределённый звонок не становится рассылкой семье. При недоступном API формируется ограниченный отчёт по имеющемуся тексту/состоянию.

**Готово, когда:** синтетические IT/RU/EN-разговоры сохраняют смысл без вымышленных имён, обещаний и срочности; нет текста/оборванный разговор отмечаются явно. Невалидный ответ модели обработан. Сбой между сохранением резюме и постановкой доставки не теряет результат; повтор отправки не повторяет уже завершённую генерацию. Все платные попытки проходят через PR-05.

## PR-09 — Семейный Telegram-бот и доставка

**Зависимости:** PR-04, PR-08. **Ветка:** `feat/telegram-family-delivery`.

**Изменения:** `telegram/`: один бот, три личных чата. CLI создаёт ограниченное по времени одноразовое приглашение для профиля; `/start` привязывает разрешённый профиль к чату. Свободного захвата по введённому имени нет. Доставка использует сохранённые адресат/назначение, очередь, аренду попытки, backoff и retry-after. Отключённый получатель приостанавливает доставку. Для нераспределённого звонка допустимо только уведомление оператору без содержания. Исходный вариант — отдельный семейный бот; использование существующего требует проверки его текущего получения обновлений.

**Готово, когда:** просроченное/повторное приглашение и захват чужого профиля отклоняются; три получателя получают свои отчёты. Проверены 429, 5xx, блокировка бота, таймаут, сбой во время доставки и рестарт очереди. При неоднозначном сетевом результате возможен повтор со стабильным ID звонка; «ровно один раз» не обещается. На исправных сервисах демонстрация «разговор на компьютере → личное резюме» занимает до 60 секунд после завершения.

## PR-10 — Управление звонками SIM7600

**Зависимости:** PR-02, PR-07 и H1. **Ветка:** `feat/sim7600-call-control`.

**Изменения:** `modem/`: выделенный AT-интерфейс, входящий вызов, ответ, отбой, состояние и метаданные. Один владелец порта, таймауты, разбор перемежающихся ответов/событий, восстановление после переподключения без сброса соседних устройств. События передаются контроллеру PR-07. Исходный адресат используется только через проверенное правило; наличие управления звонком не означает прохождение H2.

**Готово, когда:** симуляция порта покрывает фрагментацию строк, событие посреди ответа, обрыв, повторный RING и запоздалый отбой. Реально приняты/завершены звонки, включая отбой до/после ответа и занятый канал. Модем SMS-шлюза не захватывается. Управление вызовом подтверждается отдельно от готовности звука PR-11.

## PR-11 — USB-аудио между модемом и голосовым API

**Зависимости:** PR-06, PR-10 и аудиопроверка H1. **Ветка:** `feat/sim7600-usb-audio`.

**Изменения:** `audio/`: двусторонний мост с фактически проверенными форматами/частотами, преобразование при необходимости, упаковка, ограничение очередей, обработка неполных фреймов и уровней. Перебивание очищает провайдерную и локальную очередь. Служебная фраза играет без внешнего голоса. Аудио разговора не пишется в файлы или журналы.

**Готово, когда:** синтетические сигналы проверяют формат, длительность и фреймы; медленный получатель не вызывает роста памяти. Реально слышны обе стороны, нет устойчивого самовозбуждения/сильного эха, перебивание останавливает устаревшую реплику. Проверены USB-обрыв, отбой во время речи, следующий звонок без хвоста предыдущего и фраза при отказе API. Измерены задержки оборудования.

## PR-12 — Сквозной модемный сценарий

**Зависимости:** PR-08, PR-09, PR-11 и принятое решение H2. **Ветка:** `feat/end-to-end-forwarded-calls`.

**Изменения:** сборка адаптеров/обработчиков в одном приложении; live включается только с валидной конфигурацией, хранилищем и выделенным устройством. Ошибка API/бюджета вызывает локальную фразу и отбой; ошибка Telegram оставляет очередь. Режим H2 явно настроен: подтверждённый маршрут либо уточнение адресата. На старте прерванный разговор помечается соответствующим образом, без попытки продолжить исчезнувший вызов.

**Готово, когда:** одинаковый звонящий через три семейных номера получает правильный профиль/доставку; проверен скрытый caller ID. Реальные IT/RU/EN-разговоры доходят до личного отчёта, на здоровых сервисах — до 60 секунд после отбоя. Проверены второй одновременный вызов, исчерпанный бюджет, рестарт в разговоре и между отбоем/отправкой. Режим уточнения адресата допускается как результат H2.

## PR-13 — Установка и эксплуатация на SERVER

**Зависимости:** PR-12. **Ветка:** `ops/server-deployment`.

**Изменения:** Dockerfile/Compose, постоянное состояние, закрытые настройки, автозапуск, корректная остановка, права к конкретным интерфейсам и восстановление USB hotplug. При необходимости — только адресное правило для нового модема. CLI/healthcheck разделяют живой процесс, готовность модема/голоса и состояние очередей. Инструкции установки, согласованного резервного копирования SQLite/настроек, восстановления и отката версии с сохранением актуальных данных.

**Готово, когда:** на SERVER проверены перезапуск службы, загрузка после перезагрузки хоста и USB-переподключение; настройки/история сохраняются. Нет токенов/текста/аудио в логах, privileged-контейнера, общего доступа ко всем USB или публичного порта по умолчанию. Сравнение до/после подтверждает работу SMS-шлюза. Восстановление репетируется отдельно; откат не удаляет действующий том и не накатывает старую историю поверх новых звонков.

## PR-14 — Приёмка семьи и первый выпуск

**Зависимости:** PR-13. **Ветка:** `test/family-pilot-release`.

**Изменения:** приёмочные сценарии, runbook владельца, подтверждённый режим маршрутизации, инструкции настройки/отключения условной переадресации, подключения профиля и разбора нераспределённого звонка. Отчёт с фактическими результатами, ограничениями, версией образа и коммитом исходников, без личных данных. Первый тег/релиз относится к проверенному коммиту.

**Готово, когда:** все три члена семьи проверили «занято», «нет ответа», именное приветствие при известном маршруте либо уточнение, личную доставку без чужих отчётов. Проверены IT/RU/EN, перебивание, 10 минут, отбой, USB/сеть/API/Telegram, восстановление очереди и сохранение текста. Бюджетный отказ испытывается уменьшенным лимитом в отдельном состоянии без траты €50; календарные границы — управляемыми часами без изменения часов SERVER. Зафиксированы фактические стоимость/задержка и сверка usage. Непройденные требования остаются открытыми; зелёного CI недостаточно для готового пилота.

## Проверка покрытия требований

| Требование | Основные PR | Фактическое подтверждение |
|---|---|---|
| Три профиля и личный адресат | 04, 07, 09, 12 | Семейная приёмка 14, решение H2 |
| Итальянское приветствие, IT/RU/EN и перебивание | 06, 07, 11 | Прослушивание, реальные звонки 12/14 |
| €50, 600 секунд и отказ без API | 05, 07, 11 | Управляемые часы/тарифы и сценарии 12/14 |
| Бессрочный текст, отсутствие записей разговора | 03, 06, 08, 11, 13 | Проверка состояния, журналов и файлов после пилота |
| Резюме за 60 секунд и повторы доставки | 08, 09, 12 | Замер, прерывание обработки/отправки |
| Восстановление на SERVER, сохранение SMS | 10, 11, 13 | Оборудование и восстановление 13/14 |

Во всех PR подтверждения делятся на автоматические и живые. Фикстуры синтетические; ключи, семейная конфигурация и содержимое разговоров остаются вне репозитория. Эта разбивка не создаёт пустые PR и не подменяет разработку плановыми статусами.

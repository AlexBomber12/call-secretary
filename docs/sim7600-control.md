# SIM7600 control core: offline preparation

`sim7600.py` accepts an injected serial object. The separate [hardware-gated phone runtime](server-operations.md) now opens the explicit device and connects control, isolated audio, Realtime and durable workers. This does **not** demonstrate H1. The read-only inspector remains separate.

The command contract follows the manufacturer's [SIM7500/SIM7600 AT manual v3.00](https://files.waveshare.com/wiki/SIM7600G-H/SIM7500_SIM7600_Series_AT_Command_Manual_V3.00.pdf): sections 2.2.6 (answer), 5.2.2 (voice hangup), and 5.2.7 (current-call snapshots). Call control disables automatic CLCC notifications before requesting snapshots. It accepts one incoming non-conference voice call. A second waiting inbound voice call leaves the owned conversation in place. Unexpected active calls, mixed sessions and snapshots with conflicting call indexes are refused.

The channel reads bounded blocks and separates response lines from unsolicited events. A definite rejection preserves synchronization. A timeout, disconnect, malformed encoding, short write or buffer overflow closes the channel; an uncertain answer/hangup is never retried on it. Reconnection requires a new channel/controller and a fresh snapshot, without adopting an existing active call or resetting USB.

Each observed incoming call has a token. Answer/hangup recheck the snapshot and token; repeated RING preserves it, while an observed replacement invalidates it. An end hint alone does not end a call that the snapshot still shows active. A clean CLCC rejection is retried once on the same synchronized channel. Partial, malformed or repeatedly rejected snapshots invalidate ownership. A terminal or new-call hint during the retry prevents continuing an old active token. The logical call retains its last known caller when an optional snapshot number is absent; this prevents missing metadata from hiding a later observed identity change. Caller metadata is kept out of representations and is never interpreted as the original family recipient.

The implemented opener probes the SIM7600 model, checks ownership, claims its stable port exclusively and uses bounded 0.1/1-second read/write timeouts. Blocking control runs outside the asyncio loop. The runtime confirms an active post-answer snapshot before opening Realtime and watches for call end/replacement. For Serial PCM, the controller checks the 8 kHz setting with `AT+CPCMFRM?`, starts `AT+CPCMREG=1` and waits for its ready response on the owned active call. It sends `AT+CPCMREG=0` only after an idle snapshot. Record USB paths, sample rate and firmware behavior in H1. Code is tested with injected boundaries; actual firmware/USB acceptance remains pending.

Hangup requires a fresh snapshot confirming the owned active call. Once another call is seen or signaled, release uses the documented indexed `AT+CHLD=1x` for supported single-digit indexes. A rejected indexed release never falls back to global hangup. Validate indexed release and waiting-call behavior on the intended firmware during H1 (SIMCom manual section 5.2.10). Snapshots and modem commands are not an atomic compare-and-swap. Identical reused call IDs with missing transition events cannot prove a call boundary. H1 must inspect actual firmware events, timing, hangup and reconnection behavior before automatic answering is enabled. A passing fake-port test does not establish firmware voice support, Vodafone routing, USB audio format, or H2 metadata.
